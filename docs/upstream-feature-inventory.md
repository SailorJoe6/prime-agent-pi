### Skill selection and name collisions

**Assessment: partial — name collision handling exists, but the default winner differs.** Upstream v0.10.5 resolves bundled skills ahead of explicit `--skill` and other discovered sources. A global `skills` exclusion such as `"-goal"` can restore a same-name override. The [upstream loader and resource tests](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/crates/pa-core/src/resources/mod.rs#L160-L201) and its [global-exclusion fixture](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/crates/pa-core/src/resources/mod.rs#L742-L775) show both behaviors.

Pi already resolves collisions and reports losers. Its [package-manager precedence](https://github.com/SailorJoe6/prime-agent-pi/blob/6cd28f90e2391441850485c94b3ff099f579ef7a/packages/coding-agent/src/core/package-manager.ts#L171-L186) puts bundled resources last among resolved sources. A [bundled-skills test](https://github.com/SailorJoe6/prime-agent-pi/blob/6cd28f90e2391441850485c94b3ff099f579ef7a/packages/coding-agent/test/builtin-skills.test.ts#L48-L63) checks that a same-name user entry comes first, and the [skills guide](https://github.com/SailorJoe6/prime-agent-pi/blob/6cd28f90e2391441850485c94b3ff099f579ef7a/packages/coding-agent/docs/skills.md#built-in-skills) documents user, project, package, and explicit-path overrides plus built-in exclusions. This is a compatibility difference, not permission to reverse the Pi default. **Next:** compare the effects of these defaults on existing same-name overrides and explicit `--skill` integrations. Bring any unavoidable change to documented Pi behavior to Joe before adopting it.

### Python skill source switching

**Assessment: unresolved for the switched import; base editable installation is present.** Upstream v0.10.5 aims to import the selected copy when switching between a bundled skill and a same-name override. Its [venv synchronization](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/crates/pa-core/src/kernel/bootstrap/venv.rs#L186-L278) drops displaced records and removes distributions that would still shadow the selected import; its [switching fixture](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/crates/pa-core/src/kernel/bootstrap/venv/tests.rs#L1144-L1223) checks source replacement. The editable-install mechanism is not itself a parity target; what matters is which callable the user gets.

Pi [syncs selected Python skills as editable installs](https://github.com/SailorJoe6/prime-agent-pi/blob/6cd28f90e2391441850485c94b3ff099f579ef7a/packages/coding-agent/src/core/kernel/bootstrap.ts#L844-L918), uses a path-keyed install record, and has [bootstrap tests](https://github.com/SailorJoe6/prime-agent-pi/blob/6cd28f90e2391441850485c94b3ff099f579ef7a/packages/coding-agent/test/kernel-bootstrap.test.ts) for initial setup and reuse. The inspected sync path does not explicitly remove a different distribution that exposes the same import name. That alone does not establish which copy a fresh Pi kernel would import on a source switch. **Next:** in a disposable venv, compare import origins on a bundled → override → bundled sequence using local fixtures, first with different distribution names and then with the same distribution name. Check the marker and Python import origin at each new session. Link any analogous defect to TASK-1 rather than opening a speculative feature task.

### What changed after the first stable factory

- **v0.10.1 — recovery and feedback.** Run-scoped child names and clearer pause details distinguish concurrent runs. Resume re-admits a failed entry; a dead worker can be replaced once. Owners receive milestone notices and the UI counts paused runs separately ([recovery #3631](https://github.com/PrimeIntellect-ai/prime-agent/pull/3631), [notices #3713](https://github.com/PrimeIntellect-ai/prime-agent/pull/3713)). Left/Right mirror Esc/Enter, and the agents view shows factory children. The [execution rules](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L218-L220) refuse even library runs when refinements are off and reject retries on resident states.
- **v0.10.2 — looping and session handling.** Entry states can take optional inputs: null on first entry and a bound output on loopback. Required entry inputs are still rejected. `import rlm` no longer hides the factory API; between-turn child prompts arrive promptly, and a final provider failure reaches the factory as an error rather than an empty success ([failure reporting](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L122); [entry and session changes](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L135-L139)).
- **v0.10.3 — Python states and session navigation.** A state can run an isolated Python function instead of spawning an agent. Arrows select a run or a state with a session; Enter or Right opens that state’s latest session and returning restores the selection. Navigation no longer stops work: two presses of Ctrl+X stop the selected run or running agent; `r` resumes a paused run. `/context` groups run cost, retaining deleted agents’ spend. Ordinary state exits no longer wake the parent each time. The dock counts stored specs beside live runs; output capture accepts longer answers (65,536 characters) and terminal bare JSON. See the [state and navigation changes](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L62-L66) and [counts and output capture](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L72-L77).
- **v0.10.4 — terminal fix.** Pasting on `/factory` no longer writes to the hidden prompt editor ([paste fix](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L20)). This repairs an existing page, not a new control.
- **v0.10.5 — skill discovery fix.** [#4084](https://github.com/PrimeIntellect-ai/prime-agent/pull/4084) corrected the bundled factory skill’s YAML description so it loads again; invalid frontmatter now produces a diagnostic ([release note](https://github.com/PrimeIntellect-ai/prime-agent/blob/033eea1705c5ae953fe7cd7a5e7e7c45317e0dfe/CHANGELOG.md#L10)). See [skill discovery and invocation](#skill-discovery-and-invocation). This did not introduce or turn on the machine library, executor, or terminal page.

**Inspection evidence, not runtime checks.** The [upstream factory tests](https://github.com/PrimeIntellect-ai/prime-agent/blob/763094e1b6a7c17450ee8399b06cda1853847ca5/prime-agent-runtime/test/test_factory.py) cover stored-spec precedence, invalid imports that persist nothing, and watching or resuming a run. The [v0.10.3 navigation tests](https://github.com/PrimeIntellect-ai/prime-agent/blob/efb25e2be62507f8a13a157545d031da213abac9/crates/pa-tui/src/factory_view/tests.rs) distinguish opening a state’s latest session from stopping a run. ### Review decision: confirmed differences versus investigations

**Confirmed at the original pin (not implemented parity):**

- Skill status and inline references; named factory library, run controls and navigation. Pi’s intentional same-name skill override stays intact.
- Prompt preview, telemetry controls and local event mirror; global model restrictions. A known difference is not approval to adopt an upstream default.
- Percentage/retention-aware compaction, shell yield and persistence, head-and-tail cell output, Python child/session controls, tool timing, print descendant waits and ACP saved-session loading. See the entries above for the existing Pi primitives in each case.
- Eco selection and credential-based search availability; provider request identity, live auth and specific adapter/MCP behaviors above. Later TASK-5 changes only the separately pinned Codex child-selection assessment.

**Unresolved; do not create gap specifications from these observations:**

| Question | Evidence needed to decide |
| --- | --- |
| Which Python skill module loads after switching sources? | Run the [disposable two-source fixture](#python-skill-source-switching) and inspect the imported marker and module path in a fresh kernel in both switch directions. Installer records alone cannot answer this. |
| What actually shipped? | Compare original Pi archive manifests, catalog digests, Slack registration metadata and dependency notices with intended inputs. In a separately authorized disposable install, verify arguments and saved state after update and rollback. |
| What reaches the wire or an extension? | Inspect the locked Azure URL builder, Google serializer and Bedrock profile chain. Trace extension-supplied model candidates through explicit selection rather than extrapolating from picker filtering. |
| Do recovery and paint preserve events and position? | Compare active versus explicitly stopped turns on restart, queued steer destination after a fork, envless Herdr attach, viewport anchoring on page prepend and input during streaming. Bracketed-paste fixtures do not decide raw Windows terminal framing. |
| What is billed after reattach? | Compare fixed synthetic parent, child and cancelled-summary usage once each across branch own/total, session stats, goal and captured telemetry. No live account is needed. |

**Validation boundary:** pinned sources, docs and fixture definitions were inspected. The documentation checks were `git diff --check` and `npm run check:test-policy`. No behavioral test, release asset, installer or provider was exercised.

### Recommended order and exclusions

Review named machine definitions (TASK-12) before run execution (TASK-13). The terminal page (TASK-14) needs run and state identities from TASK-13. Coordinate the refinement gate with TASK-17. Durable shell identity (TASK-25) precedes its roster and dock (TASK-26); bounded shell waits (TASK-24) do not depend on persistence. The executed-command card (TASK-34) concerns display only. Per-model prompts (TASK-19) can be reviewed independently of preview (TASK-18). The other specifications do not require completion of TASK-1 or a provider change.

TASK-1 remains the separate repair audit, including signed replay, accounting, retry after credential rejection, and the ACP truncation stop reason. TASK-2 addresses orphan settlement, not cancellation history. TASK-3 concerns checkout location. TASK-5 addresses later Codex child selection, not provider entitlement. Keep the [open investigations](#review-decision-confirmed-differences-versus-investigations) separate; source inspection alone cannot settle them. Do not advance a public parity version until the required features and applicable fixes for that baseline are closed.
